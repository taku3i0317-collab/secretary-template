# 区切り（手順書）

次の会話は、この会話を覚えていない。覚えているのはこのフォルダのファイルだけ。だから「ファイルに無いことは無かったこと」になる前に、全部ファイルに移す。順番どおりに進め、途中で止まったら止まった所を本人に言う。

## 0. 先に確認
- `git status` を見る。見覚えの無い変更（自分が触っていないファイル）があれば、中身を見てから本人に「これも入れていい？」と聞く
- 秘密（パスワード・鍵・認証の URL）は、会話に出ていても書かない

## 1. 決まったことを書く（ファイルに無いものだけ）
- **進み具合** → `status/<部門>.md`。各部門に必ず「次にやること」が1行あるようにする（次の会話はここから始まる）
- **本人に聞いている途中のこと** → `status/<部門>.md` に「本人の返事待ち：〇〇」と `status/本人待ち.md` の両方。これが無いと、次の会話で聞き直すことになる。書く前に**待ち点検係**を呼ぶ（カードと出力先 `work/待ち点検係/<日付>-区切り.md` を渡す）。指摘のうち「足す」「消す」を一覧に反映する（答えを推測して書かない）
- **引き継ぎ** → `status/引き継ぎ.md` を上書き：①いま動いている作業場（ID・場所・やっていること・頼んだが未読の可能性・次に届く物）②本人の返事待ち（`status/本人待ち.md` の写し）③次の会話の秘書が気をつけること。部門のファイルに書いた「状況」とは重ならないようにする（ここは動いている物と待っている物だけ）。作業場の最後の `HANDOFF.md` は、読める物だけ読んで確かめる
- **日にちが決まったこと** → `status/締め切り.md` の予定表。済んだものは状態を「済」に
- **しくみの変え方**（係を足した・手順を変えた）→ `org/decisions.md` に1行（日付・変えたこと・理由）
- **知識**（調べて分かった事実・うまくいかなかった記録）→ `knowledge/` と `knowledge/index.md` の1行
- `status/index.md` の1行が古くなっていれば上書きする

## 2. 本人の好み・気づきを書く
- 置き場所は `status/好み.md` の1か所だけ（`status/` は会話の最初に必ず読む場所なので、ここに置けば次の会話に伝わる）
- 書くのは「本人がそう言った」ことだけ。秘書の推測や、1回きりの指示は書かない。1行1つ、30行まで。増えたら古いものを削るか、まとめる
- 秘書の動き方を変える好み（「もっと短く」「係は呼ぶ前に聞いて」など）が定着してきたら、`CLAUDE.md` に移す候補として本人に聞く。移すのは本人の確認を取ってから

## 3. 保存（`git status` が空になるまで）
- 話題ごとに分けて `git add` → `git commit`（`対象: 決めたこと` の形、日本語）
- `git push`。拒否されたら `git pull --rebase` してからもう一度
- `git status` が空にならない（衝突・push できない・入れていいか分からないファイルがある）ときは、そこで止めて本人に **「まだ消さないで」** と言い、何が残っているかを書く。無理に進めない

## 4. 日誌
- `journal/<日付>_<題名>.md` に5行（決まったこと・引っかかった所・次にやること）。日付は今日、題名はこの会話の主な話題
- 3と同じように commit・push する

## 5. 最後に
- 次の会話の最初に、秘書は `status/引き継ぎ.md` を読む（CLAUDE.md の「会話の最初に必ず」）。だから「消して大丈夫」の前に、引き継ぎの「最終更新」が今日になっているかを見る
- 1〜4 がすべて済み、`git status` が空なら、**「消して大丈夫」** と1行で言う。あわせて「次の会話の最初の一手」を1行添える（status に書いた「次にやること」と同じもの）
- 消すのは本人。秘書は /clear を促さないし、代わりに新しい会話を始めない

## やらないこと
- `.claude/` と `CLAUDE.md` を本人に聞かずに書き換えない
- 未保存があるまま「消して大丈夫」と言わない
- 会話の内容を要約して journal に長く書かない。5行に入らないものは、入るべきファイル（status/ knowledge/ org/）に書く
