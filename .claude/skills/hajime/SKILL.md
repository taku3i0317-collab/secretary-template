# はじめの設定（手順書）

本人は Claude Code が初めてかもしれない。むずかしい言葉（リポ・コミット・フック・エージェント）は使わず、「ファイル」「保存」「手伝い役」と言いかえる。**一度に聞くのは1つか2つまで**。答えにくそうなら例を3つ出す。選んでもらう質問（部門の案・手順書を作るか など）には、おすすめを1つと理由を1行付ける。呼び方や予定のように本人にしか答えられない質問は、例だけでよい。全部で15〜20分を目安にする。

## 0. 続きからか見る
- `CLAUDE.md` の【まだ】と `status/index.md` を読み、済んでいる所は飛ばす
- 「これから、あなたに合わせて私（秘書）の設定を一緒に作ります。10個くらい質問します。いつでも『あとで』と言えば止められます」と1回だけ言う

## 1. 本人のこと（CLAUDE.md「本人のこと」）
1. 何と呼べばいいか
2. 今いちばん大事なこと（例：仕事に慣れる・試験・引っ越し・体を休める）
3. 話し方の好み（例：短く／やさしく／結論から／絵文字なし）

## 2. 生活と仕事を聞いて、部門を決める
- 最初は例の部門（仕事・暮らし・お金・学び・趣味）が入っている。それを見せて「ふだんの1週間で、頭を使っていることを全部あげてみて」と聞く
- 出てきたものを、秘書が3〜5個の部門にまとめ直して案を出す（例をそのまま使う・名前を変える・消す・足す）。名前は本人の言葉を使う。決めるのは本人
- 部門ごとに「何の話が来たらここか」を1行（本人の言葉から作って見せる）

## 3. 締め切りと予定
- 「この先1か月で、日にちが決まっていること」を聞く（提出・支払い・更新・予約・誕生日など）
- `status/締め切り.md` の「予定」表に `| YYYY-MM-DD | 部門 | やること | 未 |` で足す。毎週・毎月くり返すものは「くり返し」表へ

## 4. ファイルに書く（ここで初めて書く。書く前に、書く中身を本人に見せる）
1. `CLAUDE.md`：「本人のこと」の3行と「部門」の表。**CLAUDE.md の変更は許可を聞かれるので、本人に「許可を押してね」と先に言う**。判定の数字は、本人が言ったときだけ書く（無ければ【例】の行は消す）
2. `status/index.md`：部門ごとに1行（今の状態を一言）。表の左の列は CLAUDE.md の部門名と**一字一句同じ**にする（組織図がこの名前を読む）
3. `status/<部門>.md`：部門ごとに1枚。例の部門の1枚は、使うなら中身を書き直し、名前を変えたら `git mv`、使わないなら `git rm` で消す（消す前に本人に見せる）。新しい部門は `status/_部門の型.md` をコピーして、聞いた内容を入れる。表の「（例）」の字は残さない
4. `status/締め切り.md`：3で聞いた予定
5. `status/好み.md`：1-3 の話し方の好み

## 5. 手順書を作るか聞く（任意）
- 「部門ごとに、私の動き方のメモ（`/部門名` で呼べる）を作れます。作りますか？あとからでも作れます」と聞く
- 作るなら、部門ごとに `org/_手順書の型.md` を元に `.claude/skills/<英小文字の名前>/SKILL.md` を書く（名前は本人と決める。例：仕事→shigoto）。**書くたびに許可を聞かれる**ので先に言う。書いたら CLAUDE.md の部門の表の「手順書」の列に `/shigoto` のように入れる
- 作らないなら、表の「手順書」は「なし」のまま

## 5-2. 作業場（何日も続く作業・コードを書く作業）があるか聞く（任意）
- 「AI（Claude Code など）で、何日も続けて作業しているフォルダはありますか？ アプリやツールを作っている、などです。あれば、そこは私（秘書）が作業場として頼んで、報告をまとめます。なければ『なし』で」と聞く
- あれば、フォルダごとに：名前・場所（フォルダのパス）・何をしているか・今どこまで、を聞き、その部門の `status/<部門>.md` の「## 台帳」に `### 名前 — 部門` の形で書く（`status/_部門の型.md` の台帳の形）。報告は `<フォルダ>/HANDOFF.md` と書く
- 秘書がそのフォルダを読めるようにするには、本人の手が要る。おすすめを付けて案内する：「読めるようにするのがおすすめ。報告（HANDOFF.md）を私が読みに行けるので、行き来しなくて済むから。PowerShell でこの1行を打ってください」と言って、フォルダごとに1行ずつ出す：
  `cd $HOME\notes; powershell -ExecutionPolicy Bypass -File .\setup.ps1 -AddFolder "<フォルダのパス>"`
  （`$HOME\notes` は秘書のフォルダ。違う場所なら、そのパスにして出す）。打ったら、秘書のセッションを開き直すと読めるようになる、と伝える。設定ファイルは秘書には書けない（そういう決まり）
- 作業場のセッションを今すぐ立てる必要はない。頼みたいことが出たときに立てる（CLAUDE.md の「作業場」）

## 6. 係（手伝い役）は今は作らない
- 「たくさん案を出して比べたいときに、手伝い役を足せます。必要になったら『○○の係を作って』と言って」とだけ言う。`roles/roster.md` は最初から入っている点検係（月1回の `/tenken` で使う）だけのままでよい

## 7. 保存して、確かめる
1. `git add` → `git commit -m "はじめの設定: 部門と予定を決めた"` → `git push`（push できなければ、そう言って止める。README の「うまくいかないとき」を案内する）
2. `org/decisions.md` に1行（今日の日付・部門を決めた・理由は本人の生活に合わせて）
3. 「右の組織図に部門が出ているか見てください」と言う（出ていなければ README の組織図の所を案内）
4. 最後に「明日からは、思いついたことを何でもここに話しかけてください。予定が近づいたら最初に言います。会話が長くなったら /kugiri と打ってください」と言って終わる

## やらないこと
- 本人が言っていないことを推測で status に書かない
- 健康・お金・人間関係のくわしいことを聞き出さない（本人が話したら、書いていいか聞く）
- 秘密（パスワード・カード番号）を聞かない。言われても書かない
- `.claude/settings.json`・`.claude/agents/`・`.claude/scripts/` は触らない（できないようになっている）
