# 秘書テンプレート

話しかける相手を「秘書」ひとつにして、毎日のこと（仕事・家・予定・調べもの…）をまかせるための器です。Claude Code（Claude のアプリの「Code」）で動きます。

- 秘書は、このフォルダのファイルを毎回読んでから答えるので、前の話を説明し直さなくていい
- 決まったこと・予定は、秘書がファイルに書いて保存する（GitHub に自分だけが見られる形で残る）
- たくさん案を出して比べたいときは、秘書が「係」（手伝い役）を呼ぶ
- お金が出ること・外に送ることは、秘書は必ずあなたに聞く
- 右側に「組織図」が出て、いま誰が動いているかが見える（soshiki-zu）

**もう AI を使っている人へ**：用事ごとにチャットや窓を開くのをやめて、Claude Code の作業の入口を秘書ひとつにまとめる（1本化する）しくみです。話はファイルに残るので、会話を消しても続きから話せます。前と後の比べ・図・1日の例・何を聞かれるか・向かないことは [docs/秘書ひとつにする理由.md](docs/秘書ひとつにする理由.md) に。

```
あなた → 秘書 → 部門（仕事・暮らし…）→ 必要なときだけ係
              ↘ 何日も続く作業・コード → 作業場（別フォルダの会話）に頼み、報告（HANDOFF.md）を読んでまとめる
              ↘ 決まったことは status/ などのファイルに残る → 次の会話の最初に読む
```

部門は例が入っているだけです。最初に `/hajime` と打つと、秘書があなたの生活や仕事を聞いて、自分で設定を埋めます。

---

## はじめかた（30分）

### 0. 用意するもの
- **Windows の PC**（Mac・Linux では、会話の最初に予定を出すしくみ（PowerShell のスクリプト）が動かない）
- **Claude の有料プラン（Pro 以上）**。無料プランでは Claude Code が使えない
- **GitHub のアカウント**（無料でよい）。https://github.com/signup

### 1. アプリを2つ入れる（10分）
1. **Git**：https://git-scm.com/download/win から入れる。途中の質問は全部そのまま「Next」でよい
2. **Claude のデスクトップアプリ**：https://claude.ai/download から入れて、Claude のアカウントでログインする

### 2. このテンプレートから自分のフォルダを作る（5分）
1. この GitHub のページの右上の緑のボタン **「Use this template」→「Create a new repository」**
2. Repository name に `notes`（好きな名前でよい）、**Private** を選んで「Create repository」
3. できたページの緑の「Code」ボタンを押し、出てきた URL（`https://github.com/あなたの名前/notes.git`）をコピーする

### 3. PC に持ってきて、準備する（1行・5分）
スタートメニューで「PowerShell」を開き、下の1行を貼って Enter。`<URL>` の所は、`<` `>` も含めて 2-3 でコピーした URL に置きかえる。

```powershell
cd $HOME; git clone <URL> notes; cd notes; powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

- 初めてのときは、ブラウザで GitHub のログインが出るので許可する。これで `C:\Users\あなた\notes` ができる
- そのあと準備のスクリプト（`setup.ps1`。このフォルダに入っている）が動き、やることを最初に画面に出してから、1つずつ聞く：
  1. Git に名前とメールが入っているか。無ければ聞かれるので打つ（メールは、GitHub の Settings → Emails にある `…@users.noreply.github.com` の形を使うと、本物のアドレスが記録に残らない）
  2. 秘書の設定ファイルがそろっているか（見るだけ）
  3. 組織図（soshiki-zu）を入れるか（Enter で「はい」）。記録のボタン（kiroku-botan）は聞かれるだけで、Enter なら入れない
  4. 最初の保存（commit・push）をするか
- 何かを変える前に必ず聞く。もう済んでいる所は飛ばすので、途中で止まったら同じ1行をもう一度流せばよい（2回目からは `cd $HOME\notes; powershell -ExecutionPolicy Bypass -File .\setup.ps1` だけでよい）
- 最後に「準備できました」と出れば終わり。「まだのこと」が出たら、書いてあるとおり直してもう一度流す
- `-ExecutionPolicy Bypass` は「このスクリプトを1回だけ動かしてよい」という意味。パソコンの設定は変えない。ネットからスクリプトを取ってきて流すことはしない

### 4. 秘書を開く（3分）
1. Claude のデスクトップアプリを開き、左上の **「Code」** を選ぶ
2. フォルダを選ぶ所で、3 でできた `notes` フォルダを選んで、新しいセッションを始める（「セッション」＝秘書との1つの会話。左の一覧に並ぶ）
3. 「このフォルダを信頼しますか」と出たら、信頼する（信頼しないと、このフォルダの設定が読まれない）
4. 会話の最初に「締め切り7日以内: なし」「inbox 未処理: 0件」のような行が出ていれば、準備ができている（出なければ下の「うまくいかないとき」）

### 5. 組織図（soshiki-zu）を見る
soshiki-zu は、このフォルダの `roles/roster.md` と `status/index.md` を読んで、右側に組織図を出す追加機能（Claude Code のプラグイン）。3 の準備で入れていれば、入力欄に `/reload-plugins` と打つと右に「組織図」が出る（出ないときは `/soshiki`）。

準備で「claude の命令が使えない」と出て入らなかったときだけ、アプリの画面から入れる（公開されている GitHub のリポジトリから入れる。ログインはいらない）：
1. 入力欄の横の **「+」→「Plugins」→「Add marketplace」** に `taku3i0317-collab/soshiki-zu` と入れる
2. **「Add plugin」** で soshiki-zu を選んで入れる（範囲を聞かれたら一番上の user）
3. 入れたら、入力欄に `/reload-plugins` と打つ。右に「組織図」が出る（出ないときは `/soshiki`）
4. 新しい版が出たら、`+` → Plugins で soshiki-zu を更新して `/reload-plugins`

### 6. 始める（10〜20分）
入力欄に **`/hajime`** と打つ。秘書が質問してくるので答える。途中で「許可しますか」と聞かれたら、内容を見て許可する（秘書が自分の指示書 `CLAUDE.md` を書き換えるとき・ファイルを消すときは、毎回聞くようになっている）。「拒否」を押しても壊れない。秘書が「書けなかった」と言うので、もう一度頼めばよい。

`/hajime` はたくさん読み書きするので、有料プランの使える量（5時間ごとの枠）を少し多めに使う。

**モデルは Sonnet で十分**。秘書の仕事（話を聞く・ファイルに書く・予定を出す）には、いちばん重いモデル（Opus）は要らない。Sonnet にすると、同じ枠でずっと長く話せる。切り替えは、入力欄に `/model sonnet` と打つ（デスクトップアプリなら、入力欄のそばのモデルの名前を押して Sonnet を選んでもよい）。新しい会話を始めたら、入力欄のそばのモデルの名前が Sonnet になっているかを一度見る。

終わると、右の組織図にあなたの部門が出て、秘書の設定が保存される。

### 7. ふだんの使い方
- 思いついたことは何でも秘書に話しかける。予定や締め切りを言えば、秘書が覚えておいて、7日前から会話の最初に教えてくれる
- アプリやツールなど、ほかのフォルダで Claude Code の作業をしているなら、それも秘書に頼む。秘書がそのフォルダの会話（作業場）を立てて頼み、報告をまとめて伝える。秘書にそのフォルダを読ませるには、1回だけ `cd $HOME\notes; powershell -ExecutionPolicy Bypass -File .\setup.ps1 -AddFolder "<フォルダ>"`（`/hajime` でも案内される。くわしくは docs の「作業場」）
- 会話が長くなったら **`/kugiri`** と打つ。秘書が大事なことを保存してから「消して大丈夫」と言うので、そうしたら新しいセッションを始める
- 月に1回、**`/tenken`**（点検）と打つ。増えた許可・止まっている依頼・使っていない係を秘書が見て、あなたがやることをまとめる。許可の画面では「今後聞かない」ではなく「今回だけ」を押すのがおすすめ（増えた許可は設計の外になるから）

## おすすめ：記録のボタン（kiroku-botan）
毎日のこと（ごはん・洗濯・そうじ・運動…）を、右のペインのボタン1つ（または1行打つだけ）で記録する。何を記録するかは自分で決める。会話の最初に「今日の記録」が1行出て、「洗濯 5日前←目安超え」のように教えてくれる。
1. 秘書に「記録のボタンを使いたい。`org/_生活の記録の型.md` から `status/生活.md` を作って」と頼む。秘書が「毎日記録したいこと」「何日ごとが目安のこと」を聞いて、「ボタン」と「間隔」の表を作る（聞かれなかったら「何を記録するか先に聞いて」と言う）
2. 組織図の下にも同じ記録のボタンが出るので、組織図を入れていればこれで使える。別のペインでも見たいときは kiroku-botan を入れる：3 の準備の1行をもう一度流して kiroku-botan に `y` と答える（または 5 と同じ画面で `taku3i0317-collab/kiroku-botan`）。`/reload-plugins` → `/kiroku`
3. ボタンを押すか、項目の名前だけを1行打つ（例：`洗濯`、少し前なら `洗濯 9:30`、しない日は `洗濯 なし`）。記録は `journal/記録/` に1行ずつたまる

`status/生活.md` が無いあいだは、記録のしくみは何もしない。項目を増やす・消すときは、秘書に「記録のボタンに○○を足して」と言えばよい。

## 開発中：スマホから話す（Remote Control）
家の PC で動いている秘書に、スマホの Claude アプリから話しかける機能。手順をまだ確かめている途中なので、ここは確かめ終わったら書き足す。
- 要るもの：Claude の有料プラン（Pro 以上）、スマホの Claude アプリ（同じアカウントでログイン）、話すあいだ PC が起きていること
- 今わかっている入り口：秘書のセッションの画面で Remote Control をオンにすると、スマホのアプリにそのセッションが出る

## うまくいかないとき
- **まず**：PowerShell で `cd $HOME\notes; powershell -ExecutionPolicy Bypass -File .\setup.ps1` を流す。足りない所を「!!」で教えてくれる（済んだ所は飛ばす）
- **会話の最初に「締め切り7日以内」「inbox 未処理」の行が出ない**：セッションを開き直す。「このフォルダを信頼しますか」で信頼したかも見る
- **`git push` で止まる**：上の準備の1行を流すと、push の所でログインの画面が出る
- **組織図が出ない**：`/reload-plugins` → `/soshiki`。それでも出なければ、5 の marketplace の名前の綴りを見る
- 困ったら、秘書に「○○がうまくいかない」とそのまま話しかけてよい

## このしくみが止めていること
設定（`.claude/settings.json`）の1行ずつが何を防ぎ、外すと何が起きるかは `org/design.md` の「なぜこの設定か」に。設定をいじる前に読む。
- 消す・上書きする操作（ファイルの削除、保存した履歴の書き換え）は、秘書にはできない
- 秘書は、自分の設定（`.claude/settings.json`）・係の定義・スクリプトを変えられない。変えるのはあなたが手で
- お金が出ること・外に出ること（メール・投稿・人への連絡）は、必ずあなたに聞く
- パスワードやカード番号は、ファイルにも会話にも書かない

## 目次（秘書が最初に読む）
- `CLAUDE.md` — 秘書への指示書。本人のこと・部門・ルール
- `status/` — 今の状況。`index.md`（各部門1行）、`締め切り.md`、`好み.md`、部門ごとの1枚
- `roles/` — 係の名簿（`roster.md`）とカード
- `knowledge/` — 調べて分かったこと（`index.md` が目次）
- `inbox/` — 秘書以外からのメモ。会話の最初に秘書が片付ける
- `org/` — しくみの考え方（`design.md`）・変えた記録（`decisions.md`）・型
- `journal/` — 日誌（普段は読まない）
- `docs/` — 人が読む説明（秘書は普段読まない）
- `setup.ps1` — 準備の1行で動くスクリプト（人が流す。秘書は流さない）
- `work/` — 係の返事の本文（保存しない）
